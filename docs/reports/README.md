# 周报与复盘

## 目录约定

```text
docs/reports/
├── 2026-W48-周报.md                    周报，按 ISO 周编号
├── 2026-11-阶段总结-猫耳头带v1.2.md     阶段总结，按里程碑
└── 2026-11-20-复盘-舵机烧毁.md          复盘，按事件与日期
```

命名统一：`YYYY-*`，方便按时间排序。不要用"周报1""新周报""最终版"。

## 各自解决什么问题

| 类型 | 频率 | 核心问题 | 长度 |
| --- | --- | --- | --- |
| 周报 | 每周 | 这周推进了什么、卡在哪、下周做什么 | 半页以内 |
| 阶段总结 | 每个里程碑 | 达成了什么指标、有哪些数据和结论 | 不限 |
| 复盘 | 事件后一周内 | 为什么会发生、怎么防止再发生 | 一页以内 |

## 三条原则

1. **写卡点比写成绩重要。** 成绩在代码和历史里都有，卡点只有你脑子里有。
2. **带数据。** "响应变快了"没有价值，"上升时间 120ms → 95ms"才有。
3. **写接下来做什么。** 没有下一步的周报等于日记。

# 0002 姿态解算采用一阶互补滤波

- 状态：已采纳
- 日期：2026-11-24
- 决策人：@goodalone-jhb
- 相关 Issue：（待补）

## 背景

猫耳头带需要由 MPU6050 输出头部俯仰角，驱动双舵机跟随。主控为 PY32F002BF15P6，
无硬件浮点，主频 24MHz。控制周期目标 10ms（100Hz）。

约束：单次解算耗时必须远小于 10ms，且代码量要能塞进有限的 Flash。

## 备选方案

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 一阶互补滤波 | 实现极简、算力占用低、参数直观（一个 alpha） | 动态性能一般，快速运动时有滞后 |
| Mahony | 精度优于互补滤波，计算量适中 | 需调两个增益，浮点运算多，PY32 上需实测耗时 |
| Madgwick | 动态响应好 | 计算量最大，低主频下难保证 100Hz |
| EKF | 理论最优，可融合多源 | 矩阵运算，Flash 与算力都不够 |
| 直接用 DMP 输出 | 主控零负担，精度可用 | 依赖 MPU6050 内部固件加载，配置复杂，出错难排查 |

## 结论

第一版采用一阶互补滤波，alpha 取 0.98，同时保留 DMP 作为备选路径。

理由：先让系统跑通闭环，把硬件与机械问题暴露出来，再谈精度。滤波算法不是当前瓶颈。

## 后果

- 正面：代码量小、参数单一、易于在低端 MCU 上调通
- 正面：可先用静态数据离线验证，再上板
- 负面：快速甩头时存在约 50~100ms 滞后，需通过前馈或提高 alpha 折中
- 负面：陀螺零漂未做在线估计，长时间运行会累积误差，需定期用加速度计校正或加静止检测
- 后续工作：采集实际运动数据，评估 Mahony 的耗时与收益，必要时升级

## 推翻条件

- 实测滞后影响跟随体感，且提高采样率无法缓解
- 需要输出偏航角（互补滤波对偏航无效，必须有磁力计或其他参考）
- 主控升级到带 FPU 的型号

# 硬件约定

这些约定是为了让"这块板子是谁画的、哪个引脚是什么、改过几版"这类问题有唯一答案。
不遵守的代价通常出现在比赛现场。

## 一、命名规则

### 项目与版本

```text
<功能缩写>_<板型>_v<主>.<次>
paw_headband_main_v1.2
```

| 字段 | 含义 |
| --- | --- |
| 功能缩写 | 英文小写，如 `paw_headband`（猫耳头带）、`gimbal`（云台） |
| 板型 | `main` 主控板 / `driver` 驱动板 / `sensor` 传感器板 / `pdb` 配电板 |
| 版本 | 主版本号改动 = 布线或封装变更；次版本号 = 元件参数、丝印修改 |

### 网络标号（Net Name）

| 类型 | 前缀 | 示例 |
| --- | --- | --- |
| 电源 | `V` / `VCC_` / `VBAT_` | `V3V3`, `V5V`, `VBAT_IN` |
| 地 | `GND` / `AGND` / `PGND` | 模拟地与功率地分开命名 |
| 控制信号 | 功能名_方向 | `SERVO1_PWM`, `IMU_SCL`, `MCU_TX2` |
| 使能与故障 | `_EN` / `_FAULT` / `_OC` | `DRV_EN`, `DRV_FAULT` |
| 调试 | `SWD_` / `UART_DBG_` | `SWDIO`, `SWCLK`, `UART_DBG_TX` |

禁止出现 `N1`、`NetC12_1` 这类默认名。所有跨页连接必须有明确网络标号。

## 二、引脚分配表

每块板子都必须在项目目录下维护一份 `pinmap.md`，格式如下。
**引脚一旦分配就锁定**，改引脚要同步改代码里的宏，并在表里记录变更。

### 示例：主控板 v1.2（PY32F002BF15P6）

| 引脚 | 功能 | 外设 | 方向 | 备注 |
| --- | --- | --- | --- | --- |
| PA0 | SERVO1_PWM | TIM1_CH1 | 输出 | 50Hz，500~2500us |
| PA1 | SERVO2_PWM | TIM1_CH2 | 输出 | 50Hz |
| PA2 | IMU_SCL | I2C1_SCL | 双向 | 4.7k 上拉至 3.3V |
| PA3 | IMU_SDA | I2C1_SDA | 双向 | 4.7k 上拉 |
| PA4 | UART_DBG_TX | USART1_TX | 输出 | 115200 8N1 |
| PA5 | UART_DBG_RX | USART1_RX | 输入 | |
| PA6 | LED_STATUS | GPIO | 输出 | 高电平点亮 |
| PA7 | KEY_BOOT | GPIO | 输入 | 内部上拉，低有效 |
| PF2 | SWDIO | SWD | 双向 | 保留，不可复用 |
| PF3 | SWCLK | SWD | 输入 | 保留，不可复用 |

规则：

- SWD 引脚永久保留，不做其他用途
- 调试串口固定在同一个引脚组，方便换板子不改线
- 同一功能在不同板子上尽量用同一外设编号，降低移植成本

## 三、电源与保护

| 项目 | 要求 |
| --- | --- |
| 输入保护 | 必须有反接保护（MOS 理想二极管或肖特基）与保险丝/自恢复保险 |
| 过压 | 超过额定 1.2 倍时钳位或关断 |
| 去耦 | 每个电源引脚就近 100nF，每组电源入口加 10uF |
| 上电时序 | 记录各轨建立顺序与延迟，写进项目 README |
| 电流余量 | 驱动电路额定电流至少为峰值需求的 1.5 倍 |
| 舵机供电 | 与主控分开供电路径，避免堵转拉低导致 MCU 复位 |

## 四、原理图与 PCB 评审

出板前必须完成一次评审，检查清单：

```text
[ ] 电源树完整：输入 → 各级转换 → 各负载，标注电压与最大电流
[ ] 所有芯片的电源引脚都有去耦，且靠近引脚
[ ] 复位电路、启动模式引脚（BOOT）状态正确
[ ] SWD 接口可用，未被外壳或结构件遮挡
[ ] 晶振/时钟源负载电容匹配，走线短且包地
[ ] I2C/SPI 上拉电阻齐全，总线电容不超标
[ ] 电机/舵机回路与信号回路分开走，地平面不被切断
[ ] 连接器定义与线序表一致，防呆方向标注在丝印上
[ ] 丝印含板名、版本号、日期、极性标记
[ ] 测试点：至少 3V3、5V、GND、调试串口、关键信号
```

评审记录写在项目目录的 `reviews/` 下，注明日期、参与人、发现的问题与处理结果。

## 五、接口与线序

所有对外接口必须有一张线序表，并且**连接器两端标注一致**。

| 接口 | 连接器 | 线序 | 电平 |
| --- | --- | --- | --- |
| 舵机 1 | 3Pin 2.54 | 1-信号 2-V+ 3-GND | PWM 3.3V |
| 调试串口 | 4Pin 1.25 | 1-3V3 2-TX 3-RX 4-GND | 3.3V TTL |
| 传感器板 | 4Pin 1.25 | 1-3V3 2-SCL 3-SDA 4-GND | 3.3V |

线序表与实物照片放在一起，避免"图上和实物反了"这类事故。

## 六、变更管理

硬件改动按影响分级：

| 级别 | 情况 | 处理 |
| --- | --- | --- |
| 小改 | 元件参数、丝印文字 | 次版本号 +1，记录在 `CHANGELOG.md` |
| 中改 | 增加/删除网络、换封装 | 次版本号 +1，更新 `pinmap.md`，通知算法组 |
| 大改 | 布局重构、主控更换 | 主版本号 +1，必须写 ADR，旧版本文档归档 |

**任何引脚变更，必须在同一个 PR 里同步修改固件中的引脚宏定义。**

## 七、实物与文档同步

```text
[ ] 板子焊接完成后，拍正反面照片存入 assets/
[ ] 实测电压/电流/温升数据写入项目 README
[ ] 已知飞线、割线、跳线在 README 中明确标注（含位置与原因）
[ ] 报废板子的故障原因写进 reviews/，不要只口头说
```

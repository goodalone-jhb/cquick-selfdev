# 算法组

负责感知、控制律、参数辨识与仿真。目标是让"能动"变成"动得准、动得稳"，并且每次调参都有据可查。

## 技术栈

| 方向 | 内容 |
| --- | --- |
| 姿态解算 | 互补滤波、Mahony、Madgwick、EKF |
| 控制律 | PID、串级控制、前馈补偿、死区补偿 |
| 数据分析 | Python（numpy / scipy / pandas / matplotlib）、Jupyter |
| 仿真 | MATLAB/Simulink、Python 数值仿真 |
| 数据采集 | 串口 / 上位机导出 CSV，按采样率对齐时间戳 |

## 工作流

```text
1. 明确指标     响应时间、超调量、稳态误差、滞后，量化到数字
2. 采集数据     上板跑，导出原始 CSV，标注采样率与量程
3. 离线验证     在 Python 里先跑通算法，看曲线，调参数
4. 移植上板     注意浮点开销、数组边界、采样周期抖动
5. 实测对比     新旧参数各跑一组，同一输入激励下比曲线
6. 记录结论     写进 tuning-log.md，参数固化到固件常量
```

**不要在板子上盲调参数。** 先在离线数据上跑通，再上板验证，能省掉大量烧录时间。

## 数据规范

采集的数据必须能回答"这是什么条件下测的"：

| 字段 | 必须 |
| --- | --- |
| 采样率 | 是 |
| 传感器量程与分辨率 | 是 |
| 硬件版本 | 是 |
| 输入激励（阶跃/正弦/手动） | 是 |
| 时间戳来源 | 是（MCU tick / 上位机时间） |

CSV 首行写注释说明上述信息，例如：

```text
# project=paw_headband hw=v1.2 rate=100Hz range=±2g/±500dps exc=step_30deg date=2026-11-24
t_ms,ax,ay,az,gx,gy,gz
0,0.01,-0.02,0.99,0.3,0.1,-0.2
```

## 常用脚本

```bash
# 画出一次阶跃响应
python scripts/plot_step.py --input data/step-20261124.csv --out figures/
```

## 调参记录要求

每条记录必须包含：日期、硬件版本、改动前后参数、现象（带数字）、数据位置、结论。
格式见 [调参记录](../docs/coding-style.md#三调参与实验记录)。

> 调参记录的价值在于，当你需要回到两周前的参数时，能找到它。
